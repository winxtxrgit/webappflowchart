## 1. สรุปสั้น

เว็บหน้าบ้านสร้างเสร็จและใช้งานได้ครบวงจรแล้ว — สมัคร เข้าสู่ระบบ สร้างภาพทั้งสามโหมด
ดูประวัติ ลบภาพ แก้โปรไฟล์ และสลับภาษาไทย/อังกฤษ

ทดสอบกับ backend จริงและ GPU จริง (RTX 3070) แล้วได้ภาพออกมาจริง

**เทคโนโลยี:** Vite + React + TypeScript · ไม่ใช้ UI framework สำเร็จรูป ระบบดีไซน์เขียนเอง

## 3. ⚠️ สิ่งที่ต้องทำก่อนเดโม

### 3.1 Backend ต้อง merge PR ที่ค้างอยู่

โค้ด backend ที่ผมเขียนเพิ่มอยู่ที่ branch **`feat/models-proxy`** มี **4 ฟีเจอร์**:

| Endpoint | ใช้ทำอะไร |
|---|---|
| `GET /api/models` | ดึงรายชื่อโมเดล/LoRA จริงจากเครื่อง AI แทนการเขียนตายในโค้ด |
| `DELETE /generations/{id}` | ลบภาพและประวัติ |
| `PATCH /auth/me` | แก้ชื่อผู้ใช้ อีเมล รหัสผ่าน |

**ถ้าไม่ merge → บนเครื่อง Pongkarm จะมีปุ่มที่กดแล้วไม่ทำงาน**
(เว็บไม่พัง มีข้อความแจ้งเตือน แต่ฟีเจอร์ใช้ไม่ได้)

### 3.2 บั๊ก backend ที่ยังไม่ได้แก้

| ปัญหา | ผลกระทบ |
|---|---|
| `main.py` ไม่ import `settings` แต่เรียกใช้ 3 จุด | `/healthz` และ `/api/status` ตอบ 500 |
| `requirements.txt` ขาด `passlib` | clone ใหม่แล้วรันไม่ขึ้น |
| **`lora_config` type ขัดกันสามฝ่าย** | **ถ้ากดเลือกสไตล์ตอนเดโม งานจะ fail** |

สองข้อแรกแก้บรรทัดเดียว ข้อที่สามต้องตัดสินใจว่าจะแก้ฝั่งไหน:
- backend รับเป็น **object** เท่านั้น
- mock AI server รับเป็น **array** เท่านั้น
- AI node จริงรับได้ทั้งสองแบบ

### 3.3 โหมด `callback` ทำให้บางค่าไม่มีผล — เว็บจัดการให้แล้ว

backend ไม่ได้ส่งข้อมูลทั้งก้อนไปให้ AI แต่**ประกอบ payload ใหม่ตาม `AI_MODE`
โดยไล่ระบุทีละ field** โหมด direct ระบุครบ โหมด callback ระบุไม่ครบ
ค่าที่ไม่ถูกระบุจึงไม่เคยไปถึงตัวสร้างภาพ ทั้งที่งานยังรายงานว่าสำเร็จ

พอไล่อ่าน payload ทั้งสองก้อนเทียบกัน พบว่าหนักกว่าที่เคยบันทึกไว้ —
`/ai/edit` ส่งแค่ prompt, image, mask, mode, steps, cfg_scale เท่านั้น:

| งาน | ค่าที่ปรับแล้วไม่มีผลในโหมด callback |
|---|---|
| txt2img | seed · sampler · สไตล์ (LoRA) — **3 อย่าง** |
| img2img / inpaint | 3 อย่างข้างบน + คำที่ไม่ต้องการ · โมเดล · ขนาดภาพ · ระดับการเปลี่ยนแปลง — **7 อย่าง** |

**ตอนนี้เว็บปิดการใช้งานตัวควบคุมเหล่านั้นให้อัตโนมัติ** พร้อมป้าย "ไม่มีผล"
และคำอธิบายว่าทำไม โดยยังเก็บค่าที่ตั้งไว้ให้ เผื่อเปลี่ยนกลับเป็นโหมด direct

ถ้า backend ไม่รายงานโหมด หรือเชื่อมต่อไม่ได้ เว็บจะ**ไม่ปิดอะไรเลย** —
ไม่รู้ก็ไม่ควรไปบอกผู้ใช้ว่าปุ่มเสีย

### 3.4 สลับ `.env` ก่อนเดโม

```ini
# frontend/.env
VITE_API_BASE_URL=http://<IP เครื่อง Pongkarm>:8000
```
แก้แล้วต้องรีสตาร์ท dev server (Vite อ่านค่าตอนเริ่มเท่านั้น)

## 4. ข้อจำกัดที่ไม่ใช่บั๊ก

สิ่งเหล่านี้ทำไม่ได้เพราะ **API ไม่รองรับ** ไม่ใช่เพราะยังไม่ได้ทำ:

- **ยกเลิกงานที่กำลังสร้าง** — AI node ทำได้ แต่ backend ไม่มี route ที่เรียกถึง
- **เปอร์เซ็นต์ความคืบหน้า** — ไม่มีโหนดไหนรายงาน เว็บจึงแสดงเวลาที่ผ่านไปแทน (ซึ่งเป็นความจริง)
- **กรองประวัติ** — `GET /generations` รับแค่ `page` กับ `page_size`
- **ตั้งค่าคุณภาพ/ฟอร์แมตภาพ** — ไม่มี field ให้ส่ง AI node เป็นคนกำหนดแล้วส่ง WebP กลับมา
- **รูปโปรไฟล์** — ตาราง `users` ไม่มีคอลัมน์เก็บ และ backend ไม่มีระบบ migration
  การเพิ่มคอลัมน์ต้องสั่ง `ALTER TABLE` บนฐานข้อมูลจริงด้วยมือ **เสี่ยงทำทั้งระบบพัง**
- **prompt ภาษาไทย** — โมเดลอ่านได้แต่อังกฤษ ต้องเพิ่มขั้นตอนแปลที่ AI node ก่อน

## 5. ข้อจำกัดของขนาดภาพ

backend กับ AI node กำหนดไม่ตรงกัน เว็บจึงบังคับ**ค่าที่แคบกว่า**เสมอ
เพื่อไม่ให้งานถูกรับแล้วไปพังตอนประมวลผล:

| ค่า | backend | AI node | เว็บใช้ |
|---|---|---|---|
| steps | 1–150 | 1–50 | **1–50** |
| cfg_scale | 0–30 | 1–20 | **1–20** |
| กว้าง/สูง | 64–2048 | 256–768 | **256–768** |
| ความยาว prompt | 2000 | 500 | **500** |

> **หมายเหตุ:** Forge บนเครื่องจริงตั้งค่าเริ่มต้นไว้ที่ **1024×1024** แปลว่า GPU ทำได้
> แต่ `ai_server/config.py` ล็อกไว้ที่ 768 — ถ้า AI Engineer ปลดล็อก เว็บแก้ไฟล์เดียวก็ตามได้ทันที
